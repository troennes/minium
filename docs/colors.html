Getting started

Colors

css/colors.css defines Minium's raw color scales. Map these scales to semantic tokens in css/theme.css to create or replace a theme without changing component styles.

Radix color scales

Minium uses color scales from Radix Colors. Each solid scale has a corresponding alpha scale. For example, --sand-* uses solid colors, while --sand-a* uses partially transparent colors. css/theme.css maps these palette tokens to semantic tokens such as --color-text, --color-surface, and --color-primary.

Separating palette tokens from semantic tokens keeps theme changes localized. To change a brand color, remap the relevant semantic tokens in css/theme.css. To replace the underlying palette, change the scale definitions in css/colors.css.

Alpha fill colors

Minium CSS uses partially transparent color tokens for many fill surfaces, such as --color-fill, --color-primary-fill, and --color-accent-fill. Partially transparent fills blend with their background. Components can therefore use the same fill tokens across different surfaces without separate hard-coded colors.

Build pruning

The production build excludes unused palette tokens. When you run npm run build, the build script finds the palette tokens referenced by css/theme.css. It then includes only those tokens in the production CSS.
